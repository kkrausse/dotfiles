* dotfiles

Shared configuration for Zsh, Git, tmux, Ghostty, Vim, Doom Emacs, and Clojure
tools.

** Configuration model

Files in this repository are shared configuration fragments. Each machine has
real local configuration files under =~= which import the shared fragments and
then add machine-specific settings. Do not symlink the live configuration files
to this repository.

This separation keeps paths, identities, credentials, work configuration, and
temporary experiments out of the shared Git worktree. It also means editing a
local override does not dirty this repository.

The copy-once entry points are in =bootstrap/=. Their repository paths are
examples; edit them if the checkout lives somewhere else on a machine.

** Set up a machine

Clone the repository, then copy—not symlink—the entry points. These commands
are for a new machine with no existing files. =cp= follows symlinks, so never
copy a bootstrap file over one of the old links: first move or unlink the link,
then copy the entry point. Never overwrite an existing real local file; merge
its machine-specific contents into the bootstrap file instead.

#+begin_src sh
DOTFILES="$HOME/Documents/repos/kkrausse/dotfiles"

cp "$DOTFILES/bootstrap/zshrc" "$HOME/.zshrc"
cp "$DOTFILES/bootstrap/gitconfig" "$HOME/.gitconfig"
cp "$DOTFILES/bootstrap/tmux.conf" "$HOME/.tmux.conf"
cp "$DOTFILES/bootstrap/vimrc" "$HOME/.vimrc"

mkdir -p "$HOME/.config/ghostty"
cp "$DOTFILES/bootstrap/ghostty_config" "$HOME/.config/ghostty/config"

mkdir -p "$HOME/.doom.d"
cp "$DOTFILES/bootstrap/doom.d/"*.el "$HOME/.doom.d/"

mkdir -p "$HOME/.claude" "$HOME/.config/opencode"
cp "$DOTFILES/bootstrap/claude_md" "$HOME/.claude/CLAUDE.md"
cp "$DOTFILES/bootstrap/opencode_agents_md" "$HOME/.config/opencode/AGENTS.md"
#+end_src

Review every copied file before starting the applications. In particular:

- Set the correct name and email in =~/.gitconfig=.
- Set the checkout path in the import statements.
- Put private and host-specific shell configuration after the shared Zsh
  source line.
- Put host-specific Emacs settings after the shared loads in =~/.doom.d/config.el=.

The local files load shared settings first, so settings placed after an import
normally act as machine-local overrides.

For a machine using this repository's old symlink layout, inspect and run
=bootstrap/migrate-symlinks.sh=. It refuses to overwrite real files and keeps
each replaced link with a =.pre-import-symlink= suffix.

*** Zsh

=~/.zshrc= sources the repository's =zshrc=. Keep credentials, work aliases,
and host-specific environment variables in the local file.

The shared history search bindings need =fzf= and:

#+begin_src sh
git clone https://github.com/joshskidmore/zsh-fzf-history-search.git \
  "$HOME/.zsh/plugins/zsh-fzf-history-search"
#+end_src

*** Git

=~/.gitconfig= owns identity, signing, credentials, and local overrides. Its
=[include]= section imports the repository's =gitconfig=.

*** tmux, Ghostty, and Vim

Their real local files use each application's native import command:

- tmux: =source-file /path/to/dotfiles/tmux.conf=
- Ghostty: =config-file=/path/to/dotfiles/ghostty_config=
- Vim: =source /path/to/dotfiles/vimrc=

*** Coding agents

=agent-instructions.md= holds the global instructions shared by Claude Code and
opencode. It is deliberately not named =AGENTS.md= or =CLAUDE.md=, so agents
working in this repository do not also load it as project instructions.

- Claude Code: =~/.claude/CLAUDE.md= imports it with
  =@/path/to/dotfiles/agent-instructions.md=. Copy =bootstrap/claude_md=.
- opencode: =~/.config/opencode/opencode.jsonc= lists it under =instructions=:

  #+begin_src jsonc
  "instructions": ["~/Documents/repos/kkrausse/dotfiles/agent-instructions.md"]
  #+end_src

  opencode does not expand =@= imports, and without a local
  =~/.config/opencode/AGENTS.md= it falls back to reading =~/.claude/CLAUDE.md=
  verbatim. Copy =bootstrap/opencode_agents_md= to keep a real local file there.

Instructions specific to one machine or one agent go in the local files.

*** Doom Emacs

=~/.doom.d= is a real directory. Its small =init.el=, =packages.el=, and
=config.el= wrappers load their shared counterparts from =doom-config/=. The
local =dotfiles.el= stores the checkout path in one place, =custom.el= remains
local, and machine-specific settings go after the shared loads in the local
=config.el=.

Run =doom sync= after first setup and whenever shared =init.el= or =packages.el=
changes.

The shared literate configuration is =doom-config/orgconfig.org=. Generated
=orgconfig.el= should not be committed.

**** Fresh-machine Emacs installation

The known-working baseline is macOS, Emacs Plus 30.2, and Doom commit
=5b5b170f7902e81826fd8efbec88eb38e23e2807= (2025-07-05). Doom's revision also
determines its bundled package pins; use this revision when reproducing the
setup rather than silently upgrading Doom. Homebrew's =emacs-plus@30= formula
may install a newer patch release than 30.2.

Install Homebrew and Git first, then:

#+begin_src sh
brew install ripgrep fd cmake libvterm
brew tap d12frosted/emacs-plus
brew install emacs-plus@30 --with-ctags --with-xwidgets

# Only clone into a new, empty location; preserve an existing Emacs install.
git clone https://github.com/doomemacs/doomemacs "$HOME/.config/emacs"
git -C "$HOME/.config/emacs" checkout 5b5b170f7902e81826fd8efbec88eb38e23e2807
#+end_src

Copy the =bootstrap/doom.d= wrappers as described above, and adjust
=~/.doom.d/dotfiles.el= to the actual dotfiles checkout. Do this before running
=~/.config/emacs/bin/doom install=; keep the existing wrapper files if the
installer offers to replace them. Then run:

#+begin_src sh
~/.config/emacs/bin/doom sync
~/.config/emacs/bin/doom doctor
#+end_src

The shared config loads =themes/my-vibrant-theme.el= and includes the =grey7=
default background preference. No local theme override or Ollama service is
needed. Keep machine-specific paths and private settings in the local wrappers.
=custom.el= is intentionally not copied: other interactive Customize settings,
trusted project-local forms, and session/cache state remain local.

**** Restore Worknotes and Org-roam

Clone =git@github.com:kkrausse/worknotes.git= using an account with repository
access. The example checkout location is
=~/Documents/repos/kkrausse/worknotes=. Preserve any existing checkout and its
uncommitted notes rather than replacing it.

Add these settings after the shared loads in =~/.doom.d/config.el=, adjusting
the paths to this machine:

#+begin_src elisp
(setq org-roam-directory
      (expand-file-name "~/Documents/repos/kkrausse/worknotes/org-roam"))
(setq org-directory (expand-file-name "~/org/"))

(add-hook! projectile-mode
  (add-to-list 'projectile-project-search-path '("~/Documents/" . 3)))
#+end_src

Create =~/org/= if needed. Org-roam autosync is enabled by the shared config;
run =M-x org-roam-db-sync= to rebuild its database from the notes. Do not copy
the old database, server sockets, package caches, or =orgconfig.el=.

**** Feature-specific dependencies and checks

- Doom icons: run =M-x nerd-icons-install-fonts= to install Symbols Nerd Font Mono.
- Markdown preview (=SPC m p=): install Bun so =bunx marked= is available.
- DuckDB REPL and Org Babel: =brew install duckdb=.
- =ghostty-web-term= (a Ghostty terminal in an xwidget) and
  =kev/markdown-preview-xwidget= need the =--with-xwidgets= build. The terminal
  also needs Node; see =doom-config/local-packages/ghostty-web-emacs/README.md=.
- Clojure: install a JDK, =clojure/tools/clojure=, =babashka/brew/babashka=,
  and =clojure-lsp/brew/clojure-lsp=; copy/merge the shared Clojure tool configs
  described below. The shared CIDER startup advice also sources
  =~/.sdkman/bin/sdkman-init.sh= and runs =sdk c java=: install SDKMAN and
  select a Java candidate, or override that advice locally when using a
  different JDK manager. Verify CIDER jack-in from a real Clojure project.
- Other language modules need their respective runtimes and language servers;
  follow =doom doctor= diagnostics for the languages used on that machine.
- Bibliography support currently expects =~/Desktop/bibliography/refs.bib= and
  =~/Desktop/bibliography/pdfs/=. Those files are not supplied by dotfiles;
  restore them separately or override the paths locally if using this feature.
- The custom browser-note sync commands use =https://kkrausse.com= and existing
  note IDs in Worknotes. They require that service and the matching notes.

After setup, launch GUI Emacs and verify the =my-vibrant= theme with a =grey7=
default background, Evil/keybindings, Org-roam note lookup and daily capture,
=M-x vterm=, and =emacsclient -e '(server-running-p)'=. The shared configuration
starts the Emacs server automatically. Test Markdown preview and the language
workflows you actually use; a successful =doom sync= alone is not a full check.

** Clojure tools

The repository also contains shared Clojure CLI, clj-kondo, and clojure-lsp
configuration. These tools do not all provide an equivalent native include
mechanism. Prefer a real local config and copy the shared baseline when an
import is unavailable; do not symlink an entire local configuration directory.

** Useful dependencies

#+begin_src sh
brew install fzf ripgrep cmake libvterm clojure/tools/clojure
brew tap d12frosted/emacs-plus
brew install emacs-plus@30 --with-ctags --with-xwidgets
#+end_src

#+begin_src sh
mkdir -p "$HOME/.vim/pack/tpope/start/vim-vinegar"
git clone https://github.com/tpope/vim-vinegar.git \
  "$HOME/.vim/pack/tpope/start/vim-vinegar"
#+end_src
